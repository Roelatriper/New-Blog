## 什么时候才选择它

只有当比赛、课程或机房明确指定 Dev-C++ 5.11 时，我才推荐这条路线。此时你的目标不是获得最新工具，而是让本机环境尽量接近正式环境。

日常练习不优先推荐 Dev-C++ 5.11，原因很直接：它使用的编辑器与工具链已经老旧，维护和现代 C++ 支持都不如小熊猫 C++、Visual Studio 或 VS Code。它仍然值得写进指南，是因为很多比赛与课程仍然会使用它。

> 比赛通知拥有最高优先级。若通知给出了安装包、编译器版本、语言标准或命令行参数，请完全按通知执行。

## 获得正确安装包

Dev-C++ 5.11 在网络上存在大量改包和重新打包版本。不要随手使用软件下载站里的“最新版”。建议按以下顺序获取：

1. 当届比赛官方提供的环境包；
2. 学校机房或指导教师提供的同版本安装包；
3. 赛事文档明确列出的下载地址。

如果只是日常写题，又没有指定版本，请改用[小熊猫 C++](../redpanda-cpp/)。

## 安装与基本配置

1. 安装到简单的英文路径，例如 `C:\Dev-Cpp`。
2. 第一次启动时完成语言、主题和字体选择。
3. 打开“工具 → 编译选项”，确认存在可用的 TDM-GCC 或赛事指定 GCC 编译器集。
4. 按赛事要求设置 C++ 语言标准。常见参数包括 `-std=c++11`、`-std=c++14` 或 `-std=c++17`，不要自行提高标准。
5. 新建源代码并保存为 `main.cpp`。

## 用 A+B 验收

```cpp
#include <iostream>

int main() {
    int a, b;
    std::cin >> a >> b;
    std::cout << a + b << '\n';
    return 0;
}
```

执行“编译运行”，输入 `1 2`，应输出 `3`。如果本地成功，再提交到比赛使用的在线评测系统。

## 赛前还要检查什么

- **语言标准一致：** 本机编译选项和正式评测标准一致。
- **头文件一致：** `bits/stdc++.h` 依赖 GCC，不是 C++ 标准库的一部分。比赛允许且评测使用 GCC 时才能放心使用。
- **本地文件已关闭：** 提交代码不要保留 `freopen`，除非比赛明确要求文件输入输出。
- **警告不是错误：** 编译警告可能仍会生成程序，但应看懂警告内容，不要一律忽略。
- **提前演练：** 至少在比赛前完整完成一次新建、保存、编译、运行与提交。

## 常见问题

### 提示 source file not compiled

确认文件已经保存为 `.cpp`，并查看编译日志中更早出现的第一条错误。最后一条提示通常只是前面编译失败的结果。

### 中文路径导致异常

旧工具链对非 ASCII 路径的兼容性较差。把工程移到 `D:\cpp\practice` 这类简单路径后再试。

### 本机通过，比赛失败

先比较编译器版本、语言标准和是否使用了非标准头文件，再检查整数溢出、未初始化变量和越界访问。
