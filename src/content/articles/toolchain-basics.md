## 概念区分

### 源代码

`main.cpp` 是文本文件。它记录了人类可读的 C++ 代码，本身不能直接运行。

### 编辑器

VS Code、小熊猫 C++ 和 Dev-C++ 都能编辑文本。语法高亮、自动缩进和补全让写代码更舒服，但编辑器本身不等于编译器。

### 编译器

GCC 中的 `g++` 或 Visual Studio 中的 MSVC 会读取源代码，检查语法与类型，并生成目标文件。不同编译器支持的语言版本、扩展和报错方式可能不同。

### 链接器

链接器把目标文件和需要的库组合成最终程序。你写 `std::cout` 时，实际还需要链接 C++ 标准库中的实现。

### 调试器

GDB 与 Visual Studio Debugger 可以暂停程序、单步执行、查看变量和调用栈。调试器需要编译器生成调试信息，例如 GCC 的 `-g`。

## 一条命令里发生了什么

```powershell
g++ main.cpp -std=c++17 -Wall -Wextra -g -o main.exe
```

- `g++`：调用 GCC 的 C++ 驱动程序。
- `main.cpp`：输入源文件。
- `-std=c++17`：按 C++17 规则解析。
- `-Wall -Wextra`：打开一组常用警告。
- `-g`：写入调试信息。
- `-o main.exe`：指定输出文件名。

从概念上看，代码会经历预处理、编译、汇编与链接。平时 `g++` 把这些步骤一次完成，所以你只看到一条命令。

## IDE 为什么看起来什么都有

IDE 是 Integrated Development Environment，即集成开发环境。Visual Studio、小熊猫 C++ 和 Dev-C++ 把编辑器、项目管理、编译命令、调试器和终端入口放进同一个界面。

点击“编译运行”时，IDE 仍然是在背后调用编译器，然后启动生成的程序。理解这一点后，遇到错误就能先判断属于哪一层：

| 现象 | 优先检查 |
| --- | --- |
| 代码没有补全、头文件标红 | 编辑器或 IntelliSense 配置 |
| 出现语法错误、链接错误 | 编译器命令和代码 |
| 找不到 `g++` | 工具链安装与 PATH |
| 断点不生效 | 调试器、Debug 配置与 `-g` |
| 程序结果错误 | 程序逻辑与输入数据 |

## VS Code 的三个配置文件

### `tasks.json`

描述“怎样构建”。它保存编译器路径、参数、输入文件和输出文件。

### `launch.json`

描述“怎样启动和调试”。它指定要运行的 `.exe`、调试器路径、工作目录与启动前任务。

### `c_cpp_properties.json`

主要服务于 C/C++ 扩展的代码理解能力，例如编译器路径、头文件搜索路径与 IntelliSense 模式。它不会代替真正的编译命令。

## `bits/stdc++.h` 是什么

它是 GCC 提供的聚合头文件，不属于 ISO C++ 标准。许多使用 GCC 的算法竞赛允许它，因此很常见；MSVC 默认没有这个头文件。

写竞赛代码时，如果评测环境明确使用 GCC，可以按习惯使用。写需要跨编译器的课程作业或项目时，应包含实际需要的标准头文件，例如 `<iostream>`、`<vector>` 和 `<algorithm>`。

## 从单文件走向项目

单个 `main.cpp` 可以直接用一条 `g++` 命令。文件增多后，需要让构建系统记录源文件、依赖、编译选项和库。常见选择是 CMake。

这份基础指南到 VS Code 配置为止，不继续展开 CMake。你现在只需要记住：编辑器负责写，编译器负责翻译，构建系统负责组织，调试器负责观察。
